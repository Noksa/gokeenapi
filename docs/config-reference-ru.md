## `keenetic` — Подключение к роутеру

Обязателен для каждой команды.

| Поле | Тип | Обязательно | По умолчанию | Описание |
|---|---|---|---|---|
| `url` | string | ✅ | — | URL роутера. Принимает IP адрес или KeenDNS имя хоста. Поддерживает `http://` и `https://`. Пример: `http://192.168.1.1` |
| `login` | string | ✅ | — | Имя пользователя администратора роутера. Переопределяется переменной окружения `GOKEENAPI_KEENETIC_LOGIN`. |
| `password` | string | ✅ | — | Пароль администратора роутера. Переопределяется переменной окружения `GOKEENAPI_KEENETIC_PASSWORD`. |
| `tls_skip_verify` | bool | ❌ | `false` | Отключить проверку TLS-сертификата только для соединения с роутером. Для внешних URL сертификат продолжает проверяться. Включите при самоподписанном сертификате роутера. |
| `timeout` | duration | ❌ | `30s` | Таймаут HTTP запросов к API роутера. Увеличьте для роутеров с большим количеством IP маршрутов, когда запросы (например, получение статических маршрутов) превышают значение по умолчанию. Принимает строки длительности Go: `30s`, `1m`, `2m`. |

## `routes` — Статические маршруты

Используется командами: `add-routes`, `delete-routes`.

Список конфигураций маршрутизации для каждого интерфейса.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `interfaceId` | string | ✅ | ID целевого интерфейса (например, `Wireguard0`). Запустите `show-interfaces` для просмотра доступных ID. |
| `bat-file` | список строк | ❌ | Пути к локальным `.bat` файлам с командами `route add`. Путь `.yaml`/`.yml` раскрывается в содержащийся в нём список `bat-file`. Относительные пути разрешаются относительно директории конфигурационного файла. |
| `bat-url` | список строк | ❌ | Удалённые URL с `.bat` файлами. Путь `.yaml`/`.yml` раскрывается в содержащийся в нём список `bat-url`. |

Для каждой записи должно быть указано хотя бы одно из `bat-file` или `bat-url`.

## `dns.records` — Статические DNS записи

Используется командами: `add-dns-records`, `delete-dns-records`.

Список статических DNS записей для создания в локальном резолвере роутера. Каждая запись сопоставляет одно доменное имя с одним или несколькими IPv4 адресами.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `domain` | string | ✅ | Доменное имя для разрешения (например, `myserver.local`). |
| `ip` | список строк | ✅ | Один или несколько IPv4 адресов, которым должен соответствовать домен. |

Пример:

```yaml
dns:
  records:
    - domain: myserver.local
      ip:
        - 192.168.1.100
        - 192.168.1.101
    - domain: db.local
      ip:
        - 10.0.0.5
```

## `dns.routes.groups` — Группы DNS-маршрутизации

Используется командами: `add-dns-routing`, `delete-dns-routing`.

Список доменных групп для маршрутизации на основе политик. Каждая группа создаёт object-group и dns-proxy маршрут на роутере. Требуется прошивка Keenetic версии ≥ 5.0.1.

Каждая запись — это одно из:

- **объект группы**
- **строковый путь** к `.yaml` файлу со списком `groups:` (общие группы для нескольких роутеров)
- **объект импорта** с ключом `file:` и необязательным переопределением `interfaceId`

**Поля объекта группы:**

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `name` | string | ✅ | Уникальное имя объекта-группы на роутере; пробелы и разделители команд роутера запрещены. |
| `interfaceId` | string | ✅ | Целевой интерфейс для маршрутизации трафика совпавших доменов (например, `Wireguard0`). Запустите `show-interfaces` для просмотра доступных ID. |
| `domain-file` | список строк | ❌ | Пути к локальным `.txt` файлам с одним доменом, IPv4-адресом или IPv4-подсетью на строку (строки, начинающиеся с `#`, являются комментариями). Путь `.yaml`/`.yml` раскрывается в содержащийся в нём список `domain-file`. |
| `domain-url` | список строк | ❌ | Удалённые URL со списками такого же формата. Путь `.yaml`/`.yml` раскрывается в содержащийся в нём список `domain-url`. |
| `file` | string | ❌ | Путь к YAML-файлу со списком `groups:`. Если задан, эта запись — импорт, а не группа. Вместе с `interfaceId` все импортированные группы используют указанный интерфейс. |

Для настоящей группы (не импорта) требуется хотя бы одно из `domain-file` или `domain-url`.

`add-dns-routing` сортирует записи группы, удаляет повторы и размещает не более 300 записей в каждой object-group роутера. Например, 397 доменов группы `facebook` создадут `facebook` (300) и `facebook-2` (97), обе с маршрутом через указанный интерфейс. При изменении источника команда обновляет обе группы; если осталось не более 300 доменов, она удаляет лишний маршрут и object-group `facebook-2`. Пустой источник оставляет существующие группы без изменений. Имена вида `facebook-2` зарезервированы для автоматических частей группы `facebook`. Перед обновлением или удалением дополнительных групп проверяются непрерывность имён, распределение доменов и маршруты. Пустая дополнительная группа после прерванного запуска может быть восстановлена. Изменение `interfaceId` переносит оба маршрута.

Доменные записи приводятся к строчным ASCII-именам через IDNA; завершающая точка удаляется. Поддерживаются IPv4-адреса и подсети; подсети приводятся к адресу сети. Правила `full:` и `domain:` поддерживаются, а `regexp:`, `keyword:` и `include:` пропускаются. Непустой источник без пригодных записей вызывает ошибку. Относительные локальные пути `domain-file` и `domain-url` внутри импортированного файла групп отсчитываются от каталога этого файла. Два dns-proxy маршрута для одной группы останавливают обновление до устранения неоднозначного состояния роутера.

Пример:

```yaml
dns:
  routes:
    groups:
      - name: streaming
        domain-file:
          - domains/netflix.txt
          - domains/youtube.txt
        domain-url:
          - https://example.com/spotify-domains.txt
        interfaceId: Wireguard0

      - name: work-vpn
        domain-file:
          - domains/internal.txt
        interfaceId: GigabitEthernet0/Vlan4

      # Импорт общих групп из файла (как есть)
      - common/shared_groups.yaml

      # Тот же файл, но все группы на Wireguard1
      - file: common/shared_groups.yaml
        interfaceId: Wireguard1
```

## `add-awg` / `update-awg` — Команды WireGuard

Эти команды не читают специфичный раздел из конфигурационного файла. Им нужен только блок подключения `keenetic`. Конфигурация WireGuard передаётся через флаг CLI `--conf-file`, указывающий на стандартный файл WireGuard `.conf`:

```ini
[Interface]
PrivateKey = <private-key>
Address = 10.0.0.2/32

[Peer]
PublicKey = <public-key>
Endpoint = vpn.example.com:51820
AllowedIPs = 0.0.0.0/0
```

| Флаг CLI | Обязательно | Описание |
|---|---|---|
| `--conf-file` | ✅ | Путь к файлу WireGuard `.conf`. |
| `--name` | ❌ (только `add-awg`) | Имя нового интерфейса. Генерируется автоматически, если не указано. |
| `--interface-id` | ✅ (только `update-awg`) | ID существующего интерфейса для обновления. |
| `--dry-run` | ❌ (только `update-awg`) | Показать unified diff предстоящих изменений и не применять их. |
